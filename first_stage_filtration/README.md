# Первичная фильтрация фотографий

Этап бинарной разметки в Яндекс Заданиях: исполнители определяют, есть ли на фотографии хотя бы одна бабочка. [Ноутбук запуска](filtration_launch.ipynb) создаёт проект, обучение, экзамен и рабочий пул, загружает фотографии и содержит отдельные команды открытия пулов.

Результат отдельного ответа — поле `label`: `true`, если бабочка есть, и `false`, если её нет. Рамки объектов на этом этапе не размечаются.

## Содержимое

| Файл | Назначение |
|---|---|
| [filtration_launch.ipynb](filtration_launch.ipynb) | Инструкция исполнителя, интерфейс задания, настройки и API-запросы запуска |
| [data/dataset.json](data/dataset.json) | 400 основных фотографий без эталонных ответов |
| [data/train.json](data/train.json) | 20 обучающих фотографий с ответами |
| [data/exam.json](data/exam.json) | 20 экзаменационных фотографий с ответами |
| [data/honeypots.json](data/honeypots.json) | 40 контрольных фотографий с ответами для рабочего пула |

Каталог `templates/` пока пуст. HTML-инструкция и шаблон интерфейса находятся непосредственно в ноутбуке, в переменных `instruction_html` и `template`.

## Правила разметки

Ответ «Да» выбирают для взрослой бабочки, включая моль и мотыльков. Частично закрытая бабочка также считается положительным примером; размер и количество бабочек значения не имеют.

Другие насекомые, гусеницы, куколки и тени без самой бабочки относятся к ответу «Нет». В интерфейсе можно увеличить изображение и выбрать ответ клавишами `1` («Да») и `2` («Нет»). Отправка страницы выполняется отдельно, ответ обязателен для каждого фото.

## Формат данных

Все четыре JSON-файла содержат массивы объектов. Основной набор хранит только URL:

```json
[
  {"photo_url": "https://example.org/photo.jpg"}
]
```

В обучении, экзамене и контрольном наборе дополнительно задан эталонный ответ типа boolean:

```json
[
  {"photo_url": "https://example.org/butterfly.jpg", "label": true},
  {"photo_url": "https://example.org/other_insect.jpg", "label": false}
]
```

Сами изображения в папке не хранятся: задания используют внешние ссылки. При загрузке эталонные ответы передаются в API через `known_solutions`.

## Настройки запуска

Значения ниже соответствуют исполняемому коду ноутбука.

| Параметр | Значение |
|---|---|
| Обучение | 1 фото на странице; для завершения требуется 1 страница; порог допуска к экзамену — 80% |
| Экзамен | Все 20 фото на одной странице; перекрытие 20 |
| Допуск к работе | Экзаменационный навык от 80% |
| Рабочая страница | 10 основных фото + 1 контрольное, с перемешиванием |
| Перекрытие основных фото | `WORK_OVERLAP = 3` |
| Оплата экзамена | `EXAM_PRICE = 1.2` ₽ за всю страницу |
| Оплата рабочей страницы | `WORK_PRICE = 0.8` ₽ за всю страницу |
| Язык исполнителя | Русский (`RU`) |
| Время на страницу | Обучение — 600 секунд; экзамен и работа — 1800 секунд |
| Приёмка платных заданий | Автоматическая |
| Срок действия платных пулов | 30 дней с момента вычисления `WILL_EXPIRE` |

Рабочий пул настроен на контроль `GOLDEN_SET`: окно `GOLDEN_HISTORY` равно числу экзаменационных фото, то есть 20. При накоплении минимум 20 контрольных ответов и доле правильных ниже 80% правило ограничивает доступ к рабочему пулу на 10 дней. В комментариях ноутбука описан учёт истории контрольных ответов в рамках проекта, включая экзамен. Дополнительные проверки скорости, капчи и согласия с большинством не настроены.

**В Markdown-ячейках ноутбука остались устаревшие значения:** перекрытие основных фото 1, пример цены экзамена 0,50 ₽ и имя `photos.json`. Фактически код использует перекрытие 3, цены из таблицы и файл `data/dataset.json`. Вывод о 40 рабочих страницах описывает разбиение 400 фото по 10 без учёта перекрытия; каждое основное фото запрашивается у трёх исполнителей.

## Как запустить

1. Из корня репозитория установите зависимости для этого этапа и откройте JupyterLab:

   ```bash
   python -m pip install requests jupyterlab ipykernel
   cd first_stage_filtration
   python -m jupyterlab filtration_launch.ipynb
   ```

   Ноутбук сохранён с метаданными Python 3.12.15. Его рабочей директорией должна быть `first_stage_filtration/`, поскольку пути к JSON заданы относительно неё. GPU и библиотеки моделей для этого этапа не нужны.

2. В первой ячейке кода задайте собственный OAuth-токен кабинета заказчика в `TOKEN`, проверьте цены, перекрытие и пороги. Не сохраняйте личный токен в публикуемой версии ноутбука. Запросы направляются в рабочий API `https://tasks.yandex.ru/api/v1`.
3. Выполняйте ячейки последовательно до раздела открытия: загрузите данные, создайте проект, обучение и его задания, экзаменационный навык, экзамен и его задания, затем рабочий пул с основными и контрольными фото. Сохраните полученные идентификаторы.
4. Выполните запросы проверки из раздела «Проверка перед запуском и модерация». В кабинете заказчика проверьте инструкцию, горячие клавиши, все 20 вопросов на экзаменационной странице и 11 фото на рабочей. Если проверка требует модерации, используйте соответствующую необязательную ячейку и дождитесь её завершения. Проверьте баланс.
5. В разделе «Открытие (реальный запуск)» отдельно откройте **обучение → экзамен → основной пул**. После открытия платных пулов исполнители смогут выполнять задания за деньги.

Повторный запуск ячеек создания создаёт новые сущности. Изменение локальных словарей не обновляет уже созданные пулы. Для продолжения существующего запуска используйте сохранённые ID; не запускайте весь ноутбук повторно без проверки текущего состояния.

## Результаты и границы этапа

Ноутбук заканчивается открытием пулов и выводом идентификаторов проекта, обучения, экзамена, рабочего пула и навыка. Выгрузка ответов, агрегация трёх голосов по фото и сохранение итогового набора в нём не реализованы.

При последующей выгрузке отделяйте обычные задания от контрольных по `known_solutions`: ответы на honeypots не являются новой разметкой. Следующий этап проекта — [проверка и исправление рамок](../bbox_review_pipeline/README.md), который использует уже подготовленные результаты фильтрации.

API-запросы в ноутбуке выполняются напрямую через `requests`, без автоматического сохранения состояния и развёрнутой обработки ошибок. Проверяйте ответы API перед переходом к следующим ячейкам.
